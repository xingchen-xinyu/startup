# 创业顾问 Skill 设计文档

- 日期：2026-10-20
- 使用者：星辰
- 状态：待评审

## 1. 背景与目标

星辰需要一个长期陪伴式的创业顾问，用于讨论创业方向、细化创意方案，并逐步形成清晰的愿景和可执行的行动计划。当前项目目录为空，从零搭建。

核心目标：

1. 理解并一起讨论创业点子，采用"先问后议、收敛到行动"的混合顾问风格。
2. 把讨论成果沉淀为可复用的项目资产（愿景、假设、决策、方案文档）。
3. 自动记录每次讨论的内容与结论；未完成的部分形成待办，下次可续接。
4. 自动维护个人基本信息，避免每次会话重复交代上下文。
5. 支持多个项目；允许尚未立项的想法先在临时区讨论，成熟后转为正式项目。

非目标：

- 不做 Web UI、数据库或外部服务，全部使用本地文件。
- 不自动执行市场调研；需要时可由用户显式调用深度研究能力。
- 不与外部项目管理工具（Jira、Notion 等）集成。
- 不做数据加密或云端同步。

## 2. 已确认的关键决策

| 决策点 | 结论 |
|---|---|
| 存放位置 | skill 本体和数据全部放在当前项目内 |
| 唤起方式 | 显式 `/startup-advisor` 与描述自动触发并存 |
| 记录时机 | 增量记录 + 会话收尾检查，不引入 hook |
| 顾问风格 | 混合：先问后议，关键节点给框架与建议，收敛到行动 |
| 档案深度 | 精简档案 + 按需专项方案 |
| 实现方式 | 单 skill + Python 3 标准库 CLI |
| 入口数量 | 只有一个入口；启动时自动检查未结束的讨论 |
| 未立项想法 | 临时区 `_inbox`，成熟后 promote 转正 |
| 目录命名 | 自动命名，允许中文；用户可显式覆盖 |

## 3. 总体架构

三层结构：

1. **技能协议层**：`SKILL.md` 定义何时触发、启动流程、讨论方式、落盘规则和脚本调用方式。
2. **自动化层**：`scripts/advisor.py` 负责确定性的文件操作（建目录、自动命名、待办增删、续接扫描、转正迁移等）。
3. **数据层**：`ventures/` 下的普通 Markdown/JSON 文件，人类可读、可手改、可备份、可纳入 git。

设计原则：

- **文件系统是唯一事实源**：不维护重复的索引文件，项目与临时想法均由脚本扫描 frontmatter 得出。
- **确定性操作交给脚本，内容表达交给模型**：脚本保证结构与一致性，模型负责撰写愿景、纪要、方案。
- **只增不删**：归档代替删除；转正用移动并保留历史。
- **失败可恢复**：原子写入；转正迁移失败时回滚到原位置。

规则：

- 截止日期可选，统一 `📅 YYYY-MM-DD`。

- 完成项保留在文件中，不删除。

## 5. 交互协议

### 5.1 唯一入口与启动流程

只有一个用户入口：`/startup-advisor`，后面可附带项目名或想法名。不提供其他用户级子命令，所有模式由自然语言识别。

每次启动执行：

1. 检查 `ventures/` 是否存在；不存在则运行 `advisor.py init`。
2. 读取 `ventures/profile.md`；不存在则启动首次结构化访谈。
3. 运行 `advisor.py resume --json`，获取未结束讨论、未完成待办、各目标下一步。
4. 向用户展示一屏"上次停在这里"（最多 3 条），包含：所属项目/临时区、日期、讨论主题、未决问题、下一步；另附待办数量和"还有 N 条"提示。
5. 等待用户选择：继续上次 / 切换到其他项目 / 在现有项目内开新话题 / 新想法（进临时区）/ 先看待办。用户直接说出目标名或新想法时跳过菜单。
6. 载入目标上下文：`PROJECT.md` 或 `IDEA.md`、最近讨论纪要、未决问题、未完成待办、决策记录。
7. 进入讨论流程。

### 5.2 目标路由

- **明确指定项目/想法**：按代号、显示名、目录名做精确匹配，再做模糊匹配；命中多个时列出候选让用户选择，不猜测。
- **在现有项目里开新话题**：在目标项目下创建新讨论纪要，不新建项目。
- **新想法且未确定是否立项**：自动创建 `_inbox/<自动命名>/IDEA.md`，直接开始讨论。
- **新项目**：用户明确说"新建项目"时，调用 `project new` 创建正式项目；若明显还在探索阶段，优先建议先进临时区。

### 5.3 讨论方法（混合式）

- 开场先复述理解，用一个问题确认没有跑偏。
- 每次只问一个最关键的问题，避免连珠炮。
- 在关键节点主动给出 2–3 条路径、分析框架或方案对比，并给出推荐与理由。
- 避免空泛鼓励；指出假设、风险和反证。
- 每次讨论至少收敛出一种产物：结论、决策、待办、待验证假设之一；纯发散也必须记录"未决问题"。
- 不重复询问个人档案中已有的信息。

内置方法（详见 `references/conversation-guide.md`）：

- 阶段模型：探索 → 验证 → 构建 → 运营。
- 问题拆解：目标用户、痛点强度、现有替代方案、付费意愿、获客渠道、壁垒。
- 假设管理：把关键判断转成可验证假设，配对验证实验与成功标准。
- 收尾模板：本次结论 / 未决问题 / 新增待办 / 下次接续点。

### 5.4 记录规则（增量 + 收尾）

| 发生什么 | 立即写入 |
|---|---|
| 明确结论 | 当前讨论纪要「结论」节 |
| 做出决定 | `decisions.md` 追加记录，并同步纪要 |
| 出现行动项 | `todos.md`，带优先级、截止日、来源 |
| 愿景/阶段/关键假设变化 | `PROJECT.md` |
| 新想法、尚未立项 | `_inbox/<自动命名>/IDEA.md` |
| 想法成熟 | `project promote` 转正 |
| 产生专项方案 | `assets/` 下新建文档 |

- `note new` 只创建纪要骨架并返回文件路径；正文（议题、要点、结论、未决问题）由技能通过文件编辑工具写入。
- 实质内容出现即写，不攒到最后。
- 收尾时机：用户说"收尾/今天就到这"、话题自然结束、或上下文即将结束时。执行 `checkpoint` 并输出：本次产出、更新后的待办、下次接续点。
- 收尾时判断纪要 `status`：仍有需讨论的问题 → `open`；只剩执行类待办 → `closed`。

### 5.5 首次个人访谈

按顺序询问，每次一个问题，允许"暂时不确定"：

1. 希望我怎么称呼你？目前主要做什么？
2. 过去的职业经历和最强的 2–3 项能力是什么？
3. 每周能投入多少时间？可投入的资金范围？
4. 有哪些人脉、渠道或行业资源可以借力？
5. 最想解决哪类问题？为什么是现在？
6. 更偏好哪种模式：全职创业、合伙人、还是副业验证？
7. 对风险和不确定性的承受度如何？
8. 未来 12 个月，你希望达到什么状态？

访谈结束后写入 profile，并进入项目选择流程。

### 5.6 转正流程

用户说"这个想法可以立项了"或讨论中判断成熟时：

1. 确认正式项目名（默认沿用想法标题）。
2. 运行 `advisor.py project promote <idea-ref> [--name <新名称>]`。
3. 脚本将目录迁移到 `ventures/<自动命名>/`（复制 → 校验 → 清理源），`IDEA.md` 转为 `PROJECT.md`，保留原想法内容到「想法起源」，补齐 `todos.md`/`decisions.md`，更新所有纪要的 `target`，更新 `.state.json`。
4. 技能向用户展示：新项目路径、保留的讨论数量、当前待办、建议的下一步。
5. 若迁移失败，脚本回滚目录，原临时区保持可用。

## 6. CLI 规格

脚本：`.claude/skills/startup-advisor/scripts/advisor.py`，仅用 Python 3 标准库。

### 6.1 命令列表

| 命令 | 说明 |
|---|---|
| `init` | 幂等创建工作区、档案模板、`.state.json` |
| `resume [--json]` | 汇总未结束讨论、未完成待办、各目标下一步 |
| `status [--json]` | 活跃目标、所有项目/想法概览、待办统计 |
| `idea new --title <标题> [--one-liner <一句话>]` | 自动命名创建临时想法 |
| `idea list [--json]` | 列出临时想法 |
| `project new --name <名称> [--one-liner <一句话>] [--stage <阶段>]` | 创建正式项目 |
| `project list [--json] [--include-archived]` | 列出项目 |
| `project show <ref> [--json]` | 项目详情、未完成待办、最近讨论 |
| `project update <ref> [--name] [--stage] [--one-liner] [--next-action]` | 更新 frontmatter |
| `project use <ref>` | 设置活跃目标 |
| `project promote <idea-ref> [--name <新名称>]` | 临时想法转正 |
| `note new <ref> --title <标题>` | 创建讨论纪要骨架，输出文件路径；正文由技能写入 |
| `note list <ref> [--open] [--limit N]` | 列出讨论纪要 |
| `note close <note-path>` | 将纪要标记为 closed |
| `decision add <ref> --title <标题> --decision <决定> [--options] [--reason] [--impact] [--source]` | 追加决策 |
| `todo add <ref> --text <内容> [--priority P0-P3] [--due YYYY-MM-DD] [--source <路径>]` | 新增待办，返回 ID |
| `todo list <ref> [--open] [--json]` | 列出待办 |
| `todo done <ref> <id>` | 标记完成 |
| `todo reopen <ref> <id>` | 重新打开 |
| `checkpoint <ref> [--next-action <文本>] [--json]` | 收尾：更新 updated、输出摘要 |
| `doctor [--json]` | 检查缺失文件、重复 ID、失效引用 |

### 6.2 自动命名

- 取名称/标题，去掉 Windows 非法字符 `<>:"/\|?*`、控制字符、首尾空白、点和空格。
- 保留中文；最长 48 字符；超出截断。
- 与已有目录撞名时追加 `-2`、`-3`。
- 命中 Windows 保留名（CON、PRN、AUX、NUL、COM1–9、LPT1–9）时加前缀 `_`。
- 没有任何名称时使用 `idea-YYYYMMDD-HHMM`。
- 目录名是稳定 ID；之后修改显示名不移动目录。需要覆盖目录名时使用显式参数。

### 6.3 引用解析

- 接受相对路径、目录名、frontmatter 中的 `name`/`title`。
- 先精确匹配，再大小写不敏感匹配，再做包含匹配。
- 命中多个时输出候选列表并以退出码 `1` 结束；不自动选择。
- 同时搜索正式项目和临时区。

### 6.4 输出与退出码

- 默认中文、紧凑、适合直接在终端阅读。
- `--json` 输出纯 JSON，供技能解析，不混入提示语。
- 退出码：`0` 成功；`1` 数据/业务错误（找不到目标、引用歧义等）；`2` 参数错误。
- 错误信息包含可执行的下一步建议。

### 6.5 文件安全

- 所有写入使用临时文件 + `os.replace` 原子替换。
- 显式 UTF-8 读写；输出流重配置为 UTF-8。
- 不提供删除命令；归档通过 `stage: archived` / `status: archived` 表达。
- 转正迁移采用"复制到目标 → 校验 → 删除源"，失败则清理目标并保留源。

## 7. 技能文件组织

### 7.1 `SKILL.md`

frontmatter：

```yaml
---
name: startup-advisor
description: 作为创业顾问与用户讨论创业方向、梳理点子、细化商业模式与行动计划，并自动记录讨论、结论、决策和待办，支持多项目与未立项想法的临时区。当用户提到创业想法、商业模式、项目方向、验证计划，或调用 /startup-advisor 时使用。
---
```

正文只包含：

1. 角色与风格。
2. 唯一入口的启动流程与续接检查。
3. 目标路由（项目 / 临时区 / 转正）。
4. 讨论方法与收敛要求。
5. 记录规则与收尾清单。
6. 脚本命令速查与调用路径。
7. 边界：不删除数据、不编造事实、敏感信息只进档案。

### 7.2 `references/conversation-guide.md`

- 阶段模型与每个阶段的判断标准。
- 提问法：澄清、挑战假设、反证、优先级排序。
- 常用框架：Lean Canvas、关键假设清单、验证实验设计、决策对比表。
- 收尾模板与续接点写法。
- 混合风格示例对话（正例/反例）。

### 7.3 `references/data-model.md`

- 所有文件格式、frontmatter 字段、ID 规则。
- 转正时的字段映射与保留规则。
- 手改文件时的注意事项。

## 8. 错误处理与安全

| 场景 | 行为 |
|---|---|
| 工作区不存在 | `init` 后继续，不报错退出 |
| 项目引用歧义 | 列出候选，请用户选择 |
| 项目不存在 | 提示可用列表，询问是否新建 |
| 纪要/待办文件缺失 | 自动从模板补建，并告知用户 |
| 待办 ID 冲突 | 生成新 ID，`doctor` 报告历史冲突 |
| 转正目标已存在 | 自动追加 `-2` 或提示指定名称 |
| 磁盘写入失败 | 保留原文件，报告错误，不留下半成品 |
| 讨论中出现敏感信息 | 只写入个人档案，不写入项目纪要 |

## 9. 测试与验收

### 9.1 自动化测试

使用标准库 `unittest`，全部在临时目录运行。覆盖：

1. `init` 幂等，重复执行不覆盖已有档案。
2. 自动命名：中文、非法字符、撞名、无标题、Windows 保留名。
3. `idea new` → `project promote`：目录迁移、IDEA 转 PROJECT、历史纪要保留、`target` 更新、失败回滚。
4. 待办：新增、列出、完成、重开、ID 唯一、来源链接。
5. 讨论：创建纪要、同日重名、关闭、续接扫描只返回 open。
6. 项目：列表扫描、精确/模糊引用、歧义报错、`use` 切换。
7. 档案：模板创建、变更记录追加。
8. `doctor`：缺文件、重复 ID、失效引用。

运行：

```bash
python -m unittest discover -s .claude/skills/startup-advisor/tests -v
```

### 9.2 端到端验收

1. 新会话运行 `/startup-advisor`，能展示"上次停在这里"。
2. 说"先随便聊聊一个想法"，无需命名即创建临时区并落盘。
3. 讨论中产生的结论、决定、待办分别出现在纪要、`decisions.md`、`todos.md`。
4. 想法成熟后执行转正，历史讨论与方案完整保留。
5. 下次启动能续接未决问题，不重复询问个人档案。
6. 多项目之间可以自由切换，引用不混淆。
7. 中途中断会话，已产生的结论不丢失。

注意：Claude Code 对新增项目技能通常需要重启会话才能发现，实现完成后需提示用户重载。

## 11. 成功标准

- 一个入口即可完成续接、切换项目、开新话题、新建想法。
- 每次讨论结束后，无需用户提醒，纪要/决策/待办均已落盘。
- 未结束讨论在下次启动时被准确识别并展示。
- 个人档案只采集一次，后续自动补充且不重复提问。
- 临时想法可以零门槛开始，转正后不丢任何历史。
- 所有数据都是本地可读文件，用户可直接查看和编辑。
